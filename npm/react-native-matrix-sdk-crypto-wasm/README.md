# react-native-matrix-sdk-crypto-wasm

[`@matrix-org/matrix-sdk-crypto-wasm`](https://github.com/matrix-org/matrix-sdk-crypto-wasm) for React Native. This is the Rust end-to-end encryption that matrix-js-sdk uses, running on Hermes, which has no WebAssembly.

Nothing is reimplemented. The package contains upstream's own JavaScript glue, generated by wasm-bindgen, plus upstream's crate compiled to WebAssembly and then translated to C by [wasm2c](https://github.com/WebAssembly/wabt/tree/main/wasm2c). A C++ TurboModule hands the glue an object that behaves like the exports of a WebAssembly instance. So matrix-js-sdk calls the same API, backed by the same Rust code, with no changes on its side.

> **Status: early.** The bridge passes its checks and benchmark in Hermes through JSI (see the [Hermes harness](../../packages/com/leonsilicon/matrix-sdk-crypto-wasm/hermes-harness/README.md)). It has been tested on iOS, in an Expo SDK 58 (React Native 0.88.1) app on the simulator, installed from the packed tarball. There, Megolm decrypt took 0.37 ms per event, and matrix-js-sdk 45's `initRustCrypto` ran unmodified through the Metro alias below. Android has not been tested yet.

## Usage

```sh
npm install react-native-matrix-sdk-crypto-wasm
```

Point matrix-js-sdk at it by aliasing the upstream package in `metro.config.js`:

```js
const { getDefaultConfig } = require("expo/metro-config");

const config = getDefaultConfig(__dirname);
const upstreamResolveRequest = config.resolver.resolveRequest;
config.resolver.resolveRequest = (context, moduleName, platform) => {
  const resolve = upstreamResolveRequest ?? context.resolveRequest;
  if (moduleName === "@matrix-org/matrix-sdk-crypto-wasm") {
    return resolve(context, "react-native-matrix-sdk-crypto-wasm", platform);
  }
  return resolve(context, moduleName, platform);
};

module.exports = config;
```

Then use matrix-js-sdk as usual (`await client.initRustCrypto(...)`). Its `initAsync()` call instantiates the native module.

Each release of this package is built from one upstream version. matrix-js-sdk pins an exact one, so they must match. `react-native-matrix-sdk-crypto-wasm/build-info.json` records the upstream tag and commit, the toolchain versions and the wasm hash.

| 0.1.0        | 18.9.0                 | 45.x          |

## Requirements

- **React Native's New Architecture.** It is a C++ TurboModule.
- **Globals the glue uses:** `TextEncoder`, `TextDecoder`, `queueMicrotask` and `crypto.getRandomValues`. Hermes in React Native 0.84+ has the first three. Install `react-native-get-random-values` (or use `expo-crypto`) for the last. The glue uses `FinalizationRegistry` when it exists (Hermes in React Native 0.88+); without it, objects are freed only when matrix-js-sdk calls `.free()`.
- **A persistent store needs `indexedDB`.** The crypto store reaches IndexedDB through the glue, exactly as on the web, and React Native has none. Install [react-native-indexeddb-sqlite](https://github.com/leonsilicon/react-native-indexeddb-sqlite) before calling `initRustCrypto`; with it, `initRustCrypto({ useIndexedDB: true })` works with or without a storage key or password. (This package defines `globalThis.global`, which the store's IndexedDB lookup needs on React Native.) Without an IndexedDB, use `initRustCrypto({ useIndexedDB: false })`, which keeps the store in memory, so keys do not survive a restart.

## How it works

- The upstream crate is built for the WebAssembly MVP feature set (no reference types, no multivalue). The glue then keeps JavaScript values in its own heap and passes only numbers across the boundary.
- `generated/c` is the wasm2c output (about 130 MB of C, compiled with `-O2` even in debug builds) plus wasm2c's runtime.
- `generated/c/jsi-bindings.cpp` (generated) has a JSI thunk for each of the module's ~700 exports. It also defines each of its ~250 imports as a call into the glue's function of the same name.
- `cpp/Wasm2cBridge.cpp` handles the rest:
  - Linear memory is exposed as `memory.buffer`, and a longer buffer is published whenever the memory grows. wasm2c's mmap allocation never moves the memory.
  - A trap becomes a `RuntimeError`.
  - JavaScript exceptions thrown by imports unwind back to the caller.
  - No signal handlers are installed.
